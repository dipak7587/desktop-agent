# Exported CrewAI project

This is a standalone sequential CrewAI application generated by the desktop app.
`project.json` contains the agents (role, goal, backstory, tools), ordered tasks,
expected outputs, explicit earlier-task context, and model-call budgets.

## Set up

Use Python 3.10–3.13 and an isolated environment:

```sh
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

On Windows activate with `.venv\Scripts\activate`. Fill in `CREWAI_MODEL` (a
CrewAI provider/model identifier) and the provider's credential variables in `.env`.
The export does not include desktop provider credentials or local provider IDs.
The CLI uses one model for all agents; edit `main.py` to customize provider routing.
For a custom endpoint, set `CREWAI_BASE_URL` as well. For example, a local
Ollama server can use `CREWAI_MODEL=openai/qwen3-coder:latest`,
`CREWAI_BASE_URL=http://localhost:11434/v1`, and `OPENAI_API_KEY=ollama`.
Some CrewAI providers require additional provider packages.

```sh
python main.py --input "Analyze this proposal and write a report"
python main.py --input "Review the project documentation" --folder /path/to/project
```

The supported tools are CrewAI BaseTool implementations for reading, listing,
and searching files. Each call asks for terminal approval and is restricted to
the explicit folder; secret-file patterns and symlinks are excluded. Custom tools defined in `project.json` are also supported. Their code is displayed
for approval before execution in a separate Python process. Custom code has ordinary
user permissions and is not restricted to the selected folder. Dependencies must
be installed explicitly; provider credentials are not inherited by custom processes.
Each tool defines `run(input)`, typed input fields, and a 1–120 second timeout.
The return value must be JSON serializable. Custom code, unlike built-in tools,
can access files, network services, or launch subprocesses. Only approve trusted code.

## Files

- `main.py`: standalone CLI and model/tool controls.
- `project.json`: editable declarative project definition.
- `crew_builder.py`: builds real CrewAI Agents, Tasks and a sequential Crew.
- `tool_factory.py`: supported CrewAI BaseTool wrappers.
- `custom_runner.py` and `custom_runtime.py`: approved custom Python execution.
- `requirements.txt`: pinned CrewAI version.

Model-call budgets apply per agent (across its tasks) and to the whole project.
Ctrl+C stops the standalone process. Desktop run history, cancellation UI, provider
routing, 15-minute deadline and cross-run concurrency controls belong to the desktop
host and are not supplied by this standalone CLI. Python execution is not sandboxed.
